# 识间 · 中文反诈骗网站 MVP

帮助用户描述可疑经历、识别危险信号，并先找到可执行的下一步。当前是纯前端测试版，无账号、后端或真实 AI 服务。

## 本地运行

要求 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址。其他命令：`npm test` 检查规则、数据迁移与备份，`npm run build` 检查 TypeScript 并生成 `dist/`，`npm run preview` 预览构建版。

## 当前功能

- 首页描述输入、三个快捷入口、首次访问提示。
- `riskAnalyzer.ts` 本地组合规则 → `riskService.ts` AI 接口层 → 统一分析结果。当前 AI 接口使用不上传数据的 mock；结果包含风险等级、危险信号、可能套路、事件阶段、优先行动、缺失信息、相关案例与图谱节点。单个词不作为诈骗定性。
- Scam Graph：10 个核心机制，点击展开具体套路，支持拖动和缩放；同一案例可关联多个节点。
- 紧急模式：六种场景及短清单。
- 12 个静态案例，含路径、危险信号和付款前后建议。
- 案件中心：可从分析结果保存案件，也可直接新建；编辑事件、金额、阶段和处理结果，管理时间线、证据状态与动态行动清单。刷新后仍保存在本设备，可删除。
- 统一事件阶段：从“刚接触”到“已结束”，另设“阶段未知”；本地规则、AI 接口、案件行动和紧急清单使用同一枚举。旧阶段在读取时转换。
- 案例、图谱节点、案件和投稿有来源类型、来源链接、验证状态与更新时间。当前静态案例和图谱均标为“示例数据 · 未验证”；分析标为“系统推测”，用户记录标为“用户经历”。当前没有“官方认定”内容。
- 图谱联动：从分析结果或案件详情进入图谱，相关节点和连接高亮，其他节点弱化。
- 案例投稿：保留原始描述，同时自动提取入口、诱饵、身份、承诺、行动、支付、损失、退出障碍、图谱节点与结果；继续使用原 `localStorage` 键，旧投稿仍可读取与展示。
- 案件中心可导出包含全部案件与投稿的 JSON、从 JSON 恢复、清空本地案件与投稿。数据异常时可另行导出原始存储文本供修复。

## 项目结构

```text
src/
  App.tsx                 页面、路由和表单
  schema.ts              案例、案件、图谱节点、证据、行动、投稿和阶段的共享类型
  CaseCenter.tsx          案件列表与详情
  caseStore.ts            案件迁移、行动建议与本地持久化
  backup.ts               JSON 备份、恢复与清空
  GraphPage.tsx           交互图谱
  riskAnalyzer.ts         本地判断规则
  riskService.ts          AI 接口契约与统一结果；当前 mock
  submission.ts           投稿结构化整理
  *.test.ts               规则、案件持久化和投稿自检
  data/cases.ts           案例数据
  data/graph.ts           图谱节点和关系
  styles.css             视觉与响应式样式
```

技术栈：React、TypeScript、Vite、Tailwind CSS、React Router、`@xyflow/react`。首版使用 Vite 默认单页部署模式，部署到静态托管时需把未知路径回退到 `index.html`。

## 隐私与边界

首页描述用于本地规则与 mock 判断，不发送给服务器。案件、投稿及首次访问提示状态写入浏览器 `localStorage`；清理浏览器数据可能删除这些记录。导出的 JSON 可能包含敏感信息，请妥善保存；导入会替换对应的本机记录，建议先导出当前数据。原始数据备份仅供修复，不能直接导入。请勿填写身份证号、银行卡号、验证码、家庭地址等敏感内容。请保留未经修改的原始证据；未来上传网站前自行遮挡无关个人信息。案例与规则仅提示行为风险，不对具体商家或个人作诈骗认定，也不替代官方核实或专业意见。

未来若接入 AI/API，应在 `riskService.ts` 中替换 mock、设置 `remote` 和具体 `destination`；首页会显示本次发送同意选项，未勾选时仍只做本地判断。真实 AI 返回内容还需做更严格的安全校验。不要静默上传原始描述、案件或投稿。`localStorage` 不是云备份，也不适合跨设备同步。

## Roadmap

- **下一阶段重点**：Scam Radar、社交媒体案例采集、AI 案例聚类、可信度体系、报案/投诉材料生成。需要先解决来源许可、核验、用户同意和隐私保护。
- **以后按需求评估**：真实 AI 判断、后端数据库、账号系统、公安/12315 接口、自动打码。
- 图片上传暂未实现。若将来加入，必须先提醒用户自行遮挡身份证号、银行卡号、家庭地址、验证码及他人隐私，并保留未经修改的原始证据。
